# 页面切换优化

## 已确认的问题

2026-09-20 排查时，前端路由通过 History API 和 React 状态切换，并不重新下载整页。但页面卸载后没有保留接口数据，重新进入需要再次等待网络；首次打开公开页面还被账号检查阻塞。从当前机器测量公网请求约 1–2 秒，而当时服务器普通接口处理约 1–6 毫秒。该采样不能代表所有用户的线路和所有时段。

## 本次调整

- 解析分享地址后，首页、视频、用户主页和话题页可以与身份检查并行加载；关注和其他登录相关页面等待身份确认。
- 公开内容在当前页面进程中缓存 15 秒，最多 64 条；相同公开资源的并发请求合并。不会写入 localStorage，刷新网页后重新获取。
- 返回公开列表或详情时，缓存仍有效即可先显示已有数据。列表点击视频时复用已经返回的视频信息，减少一次详情信息请求；视频媒体、评论与点赞状态仍各自加载。
- 私信、通知、账号、个人喜欢及关注 Feed 不进入这层缓存。公开用户主页的粉丝和关注列表属于公开资源。
- 业务写操作、登录退出和令牌刷新会清除缓存；失效前发出的旧请求不会重新填充缓存。主动重试与过期榜单游标恢复可以强制重新读取。

其他用户的公开数据变化可能在 15 秒窗口内暂未反映；本轮没有加入跨客户端推送失效，也没有缓存完整的已加载多页列表或恢复原滚动位置。

## 验证

`npm run test:navigation` 的 6 项测试通过，覆盖请求合并、缓存过期、强制刷新、私有接口排除、写入失效、旧请求回填隔离、列表信息复用和容量限制。上传的 7 项回归测试、TypeScript 检查及 Next.js 静态构建通过。CI 已纳入导航测试。

以上验证主要针对请求与缓存逻辑；尚未在用户真实网络上测量优化后的页面切换耗时，也未开展完整浏览器性能追踪。本轮不改变服务器地域、带宽或视频分发方式，首次访问未缓存内容仍受网络延迟影响。
